Drag and drop, View Controller, Outlets

Drag and drop

A Storyboard (Main.storyboard) is a visual canvas. Instead of writing code to create a table or label, you pick it from the Library and drop it on the screen. Xcode writes the hidden code for you.

View Controller

One screen of your app plus the Swift file that controls it. This app has one: the product list. In the Storyboard it is a big empty iPhone rectangle. Its code is in ViewController.swift.

Lifecycle

Making an Outlet

An outlet is a variable in code that points to something you dragged in the Storyboard. You will make five of them.

  1. Open the Storyboard and click the item, for example the Table View.
  2. Open the Assistant Editor: Editor > Assistant. The code file appears on the right half.
  3. Hold Ctrl, click the item and drag onto the code, just under class ViewController...{.
  4. Release. Connection: Outlet. Name: tableView. Click Connect.
  5. A filled circle beside the line means connected. A hollow circle means not connected, a common crash reason.

Crash message when you forget: Unexpectedly found nil while implicitly unwrapping an Optional value. It usually means an outlet is not connected, or the cell identifier or class name is wrong.

Architecture

MVC is Apple's own pattern. UIKit is built around it: UIViewController is literally the C.

MVVM adds a ViewModel between the screen and the data, so logic and state leave the ViewController.

Model

Product and NetworkService. Holds and fetches data. No UI code.

Product. Plain data. No UI code.

View

Main.storyboard and ProductCell. Shows things. Does not know where data comes from.

ViewController and Storyboard. No business logic, no API calls. It only talks to the ViewModel.

Controller

ViewModel

ViewController. Gets data from the Model, gives it to the View, reacts to taps. Sits in the middle and talks to both.

The brain. Asks the service for data, holds the list, tells the View that data changed.

Weakness to mention: the ViewController can grow huge (Massive View Controller). That is why networking sits in a separate NetworkService, and bigger apps move to MVVM.

Why companies ask for MVVM: smaller screen code, a ViewModel you can test without any screen, and a UI you can change without touching network code. Plain MVC tends to produce a Massive View Controller.

API and JSON: where the data comes from

Your JSON file is the data. An API link is only the web address where that file is stored. The app visits the address, downloads the text and decodes it.

1. The file

products.json: a list of products with id, name, price, category and image.

2. The link

Put the file on a website, such as GitHub. The website gives it an address. That address is your API link.

3. The decode

JSONDecoder turns the downloaded text into Swift Product objects. The table shows them.

Your JSON

Save this as products.json. The list sits inside a products key.

JSON is strict: no comments and no comma after the last item. A missing or extra comma makes decoding fail. Paste the file into any JSON checker site to find the mistake.

Turn the file into a link (GitHub)

This works on Windows, so you can do it before you get a Mac. I have not tested the site today, and free services can change.

  1. Make a free GitHub account. Create a new public repository, for example products-api.
  2. Click Add file > Upload files and upload products.json.
  3. Open the file on GitHub and click the Raw button.
  4. Copy the address from the browser. It looks like https://raw.githubusercontent.com/YOURNAME/products-api/main/products.json.
  5. Paste it into urlString in NetworkService.swift.
  6. Open the same address in a browser. If you see your JSON, the link works.

Until you do this, the placeholder link fails. The app then shows an error alert and your 5 built-in sample products. That is expected.

Or keep the file inside the app (no link)

Drag products.json into the Xcode project and tick "Add to targets: ProductApp". Then read it from the app. This works without internet, so it is a good fallback in an interview.

If the interviewer gives you a different API

  1. Open their link in a browser and read the JSON.
  2. Find the list. If the top level is { "something": [ ... ] }, keep a wrapper struct with that key name. If the top level is a plain [ ... ], decode the array directly: JSONDecoder().decode([Product].self, from: data) and delete the wrapper.
  3. Change the fields in Product to match the keys you want to show.
  4. Change the link string in NetworkService.swift.
  5. Leave the cell and table alone, except the field names used in configure(with:).

A public practice API many people use is https://dummyjson.com/products. Its keys differ from your file, so the names change:

If they give you an API key

APIs ask for the key in one of two ways. Their documentation says which. Your own JSON link needs none.

Links that start with http:// (no s) are blocked by iOS unless you add an exception in Info.plist. Links with https:// need nothing.

How the table gets its rows

  1. The table asks its data source how many rows: the ViewController answers products.count (5).the ViewController asks the ViewModel, which answers numberOfRows (5).
  2. For each visible row the table calls cellForRowAt. The ViewController gets a re-usable cell and calls cell.configure(with:) with products[row]viewModel.product(at: row).
  3. When the API data arrives: products = list then tableView.reloadData().onUpdate() then tableView.reloadData(). The table asks everything again.

Interview questions

Tap a question to see a short answer. Say it aloud once.

What is MVC?

Model = data (Product, NetworkService). View = what the user sees (Storyboard, ProductCell). Controller = ViewController: gets data from the Model, fills the View, handles taps.

MVC vs MVVM?

MVVM adds a ViewModel between Controller and Model to hold logic and state, which makes it easier to test. MVC is simpler and is what UIKit assumes. This app is MVC with a separate NetworkService to keep the controller slim.

What is MVVM?

Model = data, View = UI, ViewModel = logic and state. The View observes the ViewModel (here with closures). The View never calls the API directly.

Why MVVM instead of MVC?

Smaller view controllers, a ViewModel you can unit test, and UI separated from logic.

What is Codable?

A protocol (Encodable + Decodable) that lets JSONDecoder turn JSON into a Swift struct automatically.

Why [weak self]?

The network closure captures self (the view controller) strongly. If the screen closes before the call ends, it stays in memory. weak self avoids this retain cycle and leak.

Closures capture self strongly. The ViewModel holds the closure and the closure holds the view controller: a retain cycle and a memory leak. weak breaks it.

Why DispatchQueue.main.async?

Network callbacks arrive on a background thread. UI must be updated on the main thread or it can crash or glitch.

Why dequeueReusableCell?

It re-uses off-screen cells instead of creating one per row. This saves memory and gives smooth scrolling.

What is an IBOutlet?

A variable connected to a Storyboard element so code can change it. IBAction is the reverse: a function called by a tap.

Explain the ViewController lifecycle

viewDidLoad (once, setup), viewWillAppear, viewDidAppear, viewWillDisappear, viewDidDisappear.

struct vs class?

struct is a value type and is copied. class is a reference type, shared, and supports inheritance. Use struct for models.

What is the delegate / data source pattern?

The table asks its dataSource for rows and cells (numberOfRows, cellForRowAt). The delegate handles events (didSelectRow).

What is an optional?

A value that may be nil (String?). Unwrap with if let, guard let or ??. Avoid force unwrap (!).

URLSession vs Alamofire?

URLSession is Apple's built-in. Alamofire is a wrapper library. Interviews usually expect URLSession.

How would you add a loading spinner?

Add a UIActivityIndicatorView. Start it before loadProducts and stop it in the completion block, on success and on failure.

Add a UIActivityIndicatorView. Start it before loadProducts and stop it in onUpdate and onError.

How would you add pagination?

If the API supports it, use something like ?limit=20&skip=20. Load the next page in willDisplay when the last row is near, and append to products.

How would you add search?

Use UISearchController or a filteredProducts array in the ViewController. Filter, then reloadData.

Use UISearchController or a filter in the ViewModel that keeps a filtered array. The View just reloads.

Dependency injection?

Pass the NetworkService into the controller instead of creating it inside, so tests can give it a fake service.

The ViewModel receives NetworkService in its init. In tests, pass a mock service. This app already does it.
